# Запуск бекенда для фронтендера (React)

Цей файл пояснює простими словами, як підняти наш бекенд на Windows і як до нього
підключитися з React. Нічого програмувати на бекенді не треба: потрібно лише
виконати команди нижче в PowerShell.

---

## 1. З чого складається бекенд

Для роботи потрібні **три частини**. Вони запускаються в такому порядку:

| № | Що це | Навіщо | Обов'язково? |
|---|-------|--------|--------------|
| 1 | **MySQL** (база даних) | Зберігає користувачів, авто, бронювання, улюблені | Так, запускається першою |
| 2 | **API** (Python, FastAPI) | Ваш React звертається саме до нього | Так |
| 3 | **Worker** (листи) | Надсилає листи про бронювання. Зараз лише друкує їх у своєму вікні | Ні, для роботи сайту не потрібен |

Після запуску API доступний за адресою **http://127.0.0.1:8000**, а всі запити від
React йдуть на **http://127.0.0.1:8000/api/v1/...**

---

## 2. Що має бути встановлено

- **Python 3.11 або новіший**. Перевірка: `py --version`
- **MySQL 8 Server** (саме сервер; сам лише Workbench бази даних не створює).
  Перевірка: у PowerShell виконайте `Get-Service MySQL*`; має бути служба на кшталт `MySQL80`.
- **MySQL Workbench** (зручна програма, щоб виконати один SQL-скрипт).
- **Node.js** для React. До бекенду він стосунку не має.

Якщо чогось із цього немає, спочатку встановіть це.

## 3. Перший запуск (робиться один раз)

Усі команди виконуються в **PowerShell** у папці бекенду. Відкрийте її так:

```powershell
cd "D:\UAD\rental cars\car-rental-backend"
```

### Крок 1. Створіть віртуальне середовище й встановіть бібліотеки

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install --no-cache-dir -r requirements.txt
```

Це може тривати кілька хвилин. Папка `.venv` створюється всередині проєкту.
Активувати її не потрібно: усі команди нижче вже вказують на неї.

### Крок 2. Створіть файл налаштувань `.env`

```powershell
Copy-Item .env.example .env
```

Потім отримайте випадковий секрет для токенів:

```powershell
py -c "import secrets; print(secrets.token_hex(32))"
```

Скопіюйте виведений довгий рядок і відкрийте файл `.env` у Блокноті або VS Code.
Заповніть такі рядки (решту не чіпайте):

```dotenv
MYSQL_PASSWORD=придумайте_пароль_для_бази
JWT_SECRET_KEY=сюди_вставте_довгий_рядок_з_команди_вище
SEED_USER_PASSWORD=придумайте_пароль_для_тестових_акаунтів_від_12_символів
```

Правила:
- Пароль бази ви вигадуєте самі. Запам'ятайте його, він знадобиться в кроці 3.
- `SEED_USER_PASSWORD` має бути **не коротшим за 12 символів** і не містити слів
  `anna.demo`, `oleh.demo`, `iryna.demo`. Це пароль для тестових акаунтів (див. розділ 6).
- `GOOGLE_API_KEY` можна залишити **порожнім**. Тоді не працюватиме лише AI-помічник
  (поверне помилку 503), а все інше працюватиме. Ключ дає бекендер.
- **Файл `.env` ніколи не надсилайте в чат і не додавайте в Git.** Там паролі.

### Крок 3. Створіть базу даних у MySQL Workbench

1. Відкрийте **MySQL Workbench** і підключіться до локального сервера під адміністратором (root).
2. Відкрийте файл `database\create_database.sql` з папки проєкту
   (меню *File → Open SQL Script*).
3. У ньому знайдіть `REPLACE_WITH_YOUR_DATABASE_PASSWORD` і замініть на **той самий пароль**,
   який ви вказали в `.env` у `MYSQL_PASSWORD`.
4. Виконайте скрипт (кнопка з блискавкою).

Скрипт створює базу `car_rental` і користувача `car_rental_app`.
Таблиці він не створює; це робиться наступним кроком.

> Якщо користувач `car_rental_app` уже існує зі старим паролем, скрипт цей пароль не змінить.
> Тоді в Workbench виконайте окремо рядок `ALTER USER 'car_rental_app'@'127.0.0.1' IDENTIFIED BY 'ваш_пароль';`.

### Крок 4. Створіть таблиці та тестові дані

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m src.seed
```

- Перша команда створює таблиці в базі.
- Друга додає тестові авто, користувачів, улюблені та бронювання.
  Її можна запускати повторно: дублікатів не буде.

Якщо в кінці бачите рядок на кшталт `Seed finished. Created: cars=28, users=3, ...`,
усе гаразд.

## 4. Щоденний запуск (кожного разу, коли беретеся до роботи)

### 1) Переконайтеся, що працює MySQL

Зазвичай він запускається разом з Windows. Перевірка:

```powershell
Get-Service MySQL*
```

Якщо статус `Stopped`, запустіть PowerShell **від імені адміністратора** і виконайте
(назву служби візьміть з попередньої команди):

```powershell
Start-Service MySQL80
```

### 2) Запустіть API (перше вікно PowerShell)

```powershell
cd "D:\UAD\rental cars\car-rental-backend"
.\.venv\Scripts\python.exe -m uvicorn src.main:app --host 127.0.0.1 --port 8000 --reload --no-proxy-headers
```

Це вікно **залишайте відкритим**: поки воно працює, працює й бекенд.
Коли в ньому з'явиться `Application startup complete`, API готовий.
Запускайте **один** екземпляр API; не додавайте `--workers`.

### 3) Worker для листів (необов'язково, друге вікно PowerShell)

```powershell
cd "D:\UAD\rental cars\car-rental-backend"
.\.venv\Scripts\python.exe -m src.worker
```

Потрібен лише якщо хочете бачити «надіслані» листи про бронювання. Зараз вони не
відправляються по-справжньому, а друкуються в цьому вікні.

### 4) Запустіть React

Це вже у вашій папці з фронтендом (наприклад, `npm run dev` або `npm start`).

### Як зупинити

У вікні PowerShell натисніть `Ctrl + C`.

## 5. Як перевірити, що все працює

Відкрийте в браузері:

| Адреса | Що має бути |
|--------|-------------|
| http://127.0.0.1:8000/health | `{"status":"ok"}`: API живий |
| http://127.0.0.1:8000/ready | `{"status":"ready"}`: API бачить базу даних |
| http://127.0.0.1:8000/docs | Swagger: сторінка, де видно всі запити й можна їх пробувати |
| http://127.0.0.1:8000/api/v1/cars | Список авто (JSON) |

**Swagger (`/docs`) — ваш головний помічник:** там видно кожен запит, приклади тіла й
відповідей, і прямо там їх можна виконати. Щоб пробувати запити, які потребують входу,
натисніть кнопку **Authorize** і вставте `access_token` (без слова `Bearer`).

## 7. Як підключити React до цього API

### Основні правила

- **Базова адреса:** `http://127.0.0.1:8000/api/v1`
- **CORS:** бекенд дозволяє запити лише з `http://localhost:3000`, `http://127.0.0.1:3000`,
  `http://localhost:5173` і `http://127.0.0.1:5173` (Vite використовує 5173, Create React App 3000).
  Якщо ваш фронтенд на іншому порту, скажіть бекендеру: адреса додається в `CORS_ORIGINS` у `.env`.
- **Cookies не використовуються.** Вхід працює через заголовок
  `Authorization: Bearer <access_token>`.
- **Формат дат:** `YYYY-MM-DD` (наприклад, `2026-12-01`).
- **Гроші приходять рядками:** `"2400.00"`, а не числом. Для відображення перетворюйте самі.
- Усі відповіді та запити у форматі JSON.

### Вхід і токени

1. `POST /auth/register` реєстрація:
   ```json
   {
     "email": "ivan@example.com",
     "full_name": "Іван Петренко",
     "password": "мінімум-12-символів",
     "password_confirmation": "мінімум-12-символів"
   }
   ```
2. `POST /auth/login` вхід (звичайний JSON, не форма):
   ```json
   { "email": "ivan@example.com", "password": "мінімум-12-символів" }
   ```
   Відповідь:
   ```json
   {
     "access_token": "...",
     "refresh_token": "...",
     "token_type": "bearer",
     "expires_in": 900
   }
   ```
3. `access_token` живе **15 хвилин** (`expires_in` у секундах). З ним ходять на захищені адреси.
4. Коли він спливає (сервер відповідає **401**), викличте `POST /auth/refresh`
   з тілом `{ "refresh_token": "..." }`. Ви отримаєте **нову пару токенів**; старий
   `refresh_token` після цього вже не діє, тож збережіть новий. `refresh_token` живе 7 днів.
5. `POST /auth/logout` (із заголовком Authorization) завершує сесію. `GET /auth/me`
   повертає поточного користувача.

Приклад запиту з React:

```js
const API = "http://127.0.0.1:8000/api/v1";

async function api(path, { method = "GET", body, token, headers = {} } = {}) {
  const res = await fetch(`${API}${path}`, {
    method,
    headers: {
      "Content-Type": "application/json",
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
      ...headers,
    },
    body: body ? JSON.stringify(body) : undefined,
  });
  if (res.status === 204) return null; // порожня відповідь (улюблені, logout)
  const data = await res.json();
  if (!res.ok) throw { status: res.status, ...data };
  return data;
}

// Вхід
const tokens = await api("/auth/login", {
  method: "POST",
  body: { email: "anna.demo@example.com", password: "ваш_SEED_USER_PASSWORD" },
});

// Захищений запит
const me = await api("/auth/me", { token: tokens.access_token });
```

### Каталог авто (відкритий, без входу)

`GET /cars` приймає фільтри в адресі, усі необов'язкові:

| Параметр | Значення |
|----------|----------|
| `q` | пошук за текстом (марка, модель, опис) |
| `brand` | точна марка, наприклад `Toyota` |
| `category` | `economy`, `sedan`, `suv`, `premium`, `van` |
| `transmission` | `automatic`, `manual` |
| `fuel_type` | `petrol`, `diesel`, `hybrid`, `electric` |
| `min_seats` | мінімум місць (1–9) |
| `min_price`, `max_price` | ціна за добу, UAH |
| `start_date`, `end_date` | **завжди парою**: показати лише вільні на ці дати |
| `sort` | `price_asc` (за замовчуванням), `price_desc`, `newest` |
| `page`, `page_size` | сторінка й розмір (до 100) |

Приклад: `/cars?category=suv&max_price=2500&sort=price_asc&page=1&page_size=12`

Відповідь:
```json
{
  "items": [
    {
      "id": 15,
      "brand": "Toyota",
      "model": "RAV4",
      "year": 2024,
      "category": "suv",
      "transmission": "automatic",
      "fuel_type": "hybrid",
      "seats": 5,
      "daily_price": "2400.00",
      "currency": "UAH",
      "description": "Гібридний кросовер для сім'ї: економний і комфортний."
    }
  ],
  "total": 1, "page": 1, "page_size": 12
}
```

Зверніть увагу: **полів із фото (image_url) поки немає**. Картинки для карток авто
треба буде брати на фронтенді або домовитися про окреме поле з бекендером.
`GET /cars/{id}` повертає одне авто.

### Улюблені (потрібен вхід)

- `GET /favorites` список (повертається масив авто, параметри `limit` і `offset`)
- `PUT /favorites/{car_id}` додати (відповідь `204`, повторний виклик нічого не ламає)
- `DELETE /favorites/{car_id}` видалити (відповідь `204`)

### Бронювання (потрібен вхід)

- `POST /bookings` створити бронювання. **Обов'язковий заголовок `Idempotency-Key`**:
  це випадковий UUID, який ви генеруєте на фронтенді один раз на *намір* забронювати
  (`crypto.randomUUID()`). Якщо запит повторюєте через збій мережі, надішліть **той самий**
  ключ і те саме тіло, тоді бронювання не задвоїться. Для нового бронювання потрібен новий ключ.
  ```js
  await api("/bookings", {
    method: "POST",
    token,
    headers: { "Idempotency-Key": crypto.randomUUID() },
    body: { car_id: 15, start_date: "2026-12-10", end_date: "2026-12-13" },
  });
  ```
- `GET /bookings` свої бронювання (масив, `limit` / `offset`)
- `GET /bookings/{id}` одне бронювання
- `POST /bookings/{id}/cancel` скасувати (лише до дня початку)

Правила: початок від сьогодні до 365 днів уперед, тривалість 1–90 днів. День повернення
не оплачується (10–13 число = 3 доби). Статус бронювання: `confirmed` або `cancelled`.
Ціна `total_price` рахується на сервері.

### AI-помічник (потрібен вхід)

`POST /assistant/recommendations`
```json
{ "message": "Порадь авто для сім'ї та кемпінгу" }
```
Відповідь:
```json
{
  "message": "Під ваш запит варто звернути увагу на такі варіанти: ...",
  "applied_filters": { "...": "фільтри, які застосував помічник" },
  "cars": [ { "id": 15, "brand": "Toyota", "model": "RAV4", "...": "..." } ]
}
```
- Показуйте `message` як текст відповіді, а `cars` як картки. Масив `cars` може бути
  порожнім (тоді в `message` пояснення або уточнювальне запитання).
- Повідомлення від 3 до 2000 символів. Ліміт: **10 запитів на годину** на користувача.
- Запит може тривати **кілька секунд, а у разі збоїв Google і довше**: покажіть індикатор завантаження.
- Помилки: `503` (AI не налаштований, немає ключа), `502` / `504` (збій або таймаут
  Google), `429` (перевищено ліміт). Покажіть зрозуміле повідомлення й дозвольте повторити.

### Формат помилок

Звичайна помилка:
```json
{ "code": "car_not_found", "detail": "Car not found." }
```
Помилка валідації (код `422`):
```json
{ "code": "validation_error", "errors": [ { "loc": ["body", "email"], "type": "...", "message": "..." } ] }
```

| Код | Що означає |
|-----|------------|
| 401 | Немає токена або він прострочений: оновіть через `/auth/refresh` або перекиньте на вхід |
| 404 | Запису немає або він чужий |
| 409 | Конфлікт (наприклад, авто вже заброньоване на ці дати, email вже зайнятий) |
| 422 | Некоректні дані |
| 429 | Забагато спроб; зачекайте. Є заголовок `Retry-After` |
| 502 / 504 | Збій AI |
| 503 | База або AI тимчасово недоступні |

## 8. Якщо щось не працює

| Симптом | Що робити |
|---------|-----------|
| `py` або `python` не знайдено | Не встановлено Python. Встановіть 3.11+ і відкрийте нове вікно PowerShell |
| API не стартує, у вікні помилка про налаштування (`JWT_SECRET_KEY`, `MYSQL_PASSWORD`) | У `.env` залишилися заглушки `replace-with-...`. Заповніть їх за кроком 2 |
| `Access denied for user 'car_rental_app'` | Пароль у `.env` не збігається з тим, що ви вписали у `create_database.sql`. Виконайте `ALTER USER` (див. крок 3) |
| `Can't connect to MySQL server` / `/ready` повертає 503 | MySQL не запущений. Запустіть службу (розділ 4, пункт 1) |
| `alembic upgrade head` пише, що бази немає | Не виконано `create_database.sql` (крок 3) |
| `src.seed` пише `SEED_USER_PASSWORD is empty` | Заповніть `SEED_USER_PASSWORD` у `.env` (від 12 символів) |
| `src.seed` відхиляє пароль | Він закороткий або містить `anna.demo` / `oleh.demo` / `iryna.demo` |
| Порт 8000 зайнятий | Закрийте інше вікно з API або змініть `--port 8001` (тоді змініть адресу й у React) |
| У браузері помилка CORS | Порт вашого React не з переліку (3000 / 5173). Скажіть бекендеру додати його в `CORS_ORIGINS` |
| AI-помічник повертає 503 | У `.env` порожній `GOOGLE_API_KEY`. Попросіть ключ у бекендера, інше працює і без нього |
| Після перезапуску API «забулися» ліміти спроб входу | Це нормально: лічильники зберігаються в пам'яті |
